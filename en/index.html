Approach

How I work

01

Frame before coding

I start by setting what matters and how to measure it: missing an epileptic seizure costs more than a false alarm, so recall comes first; in my final-year project, five measurable success criteria were set before the first line of code.

Example: Explain My Model →

02

Check the data

Before modelling, I look for what would distort the result: 1,916 images shared by training and test removed, customers counted twice, incomplete months, amounts inflated by joins.

Example: Emotions →

03

Evaluate without cheating

An isolated test set used only once, real time order when it matters, comparison with reference models, confidence intervals. Settings are chosen on validation, never on the test set.

Example: DataBot →

04

Ship it, limits included

I go all the way to the tool people use: a dashboard with alerts, a platform for experts, PDF reports, a notebook. Every deliverable says where it can be trusted and where it cannot.
